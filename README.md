# اطلس تحلیل آموزشی — پروژه مستقل

نسخه ۲.۰.۰ · داشبورد فارسی و راست‌به‌چپ برای تحلیل نیازهای آموزشی خراسان شمالی.

این پروژه یک سایت مستقل با HTML، CSS و JavaScript است. صفحه اصلی، فونت، داده جداول و ابزارهای ساخت داخل همین پوشه هستند. برای انتشار روی GitHub Pages به نصب پکیج یا تغییر پورتال اصلی نیازی نیست.

## جایگزینی نسخه قبلی

اگر ریپوی `education-needs-bi` را قبلاً ساخته‌اید، محتویات این نسخه را در همان پوشه محلی جایگزین کنید. بسته فایل `.git` ندارد؛ تاریخچه ریپوی شما حفظ می‌شود. کلید داده مرورگر هم تغییر نکرده است.

در پوشه پروژه:

```powershell
git add .
git commit -m "Redesign table analytics dashboard v2.0.0"
git push
git tag v2.0.0
git push origin v2.0.0
```

تنظیم Pages همان `main` و `/(root)` می‌ماند. اگر ریپو را هنوز نساخته‌اید، مراحل زیر را انجام دهید.

## انتشار سریع در GitHub Pages

۱. فایل ZIP را استخراج کنید و در حساب `saeideeshghi` یک ریپوی جدید با نام `education-needs-bi` بسازید. برای GitHub Free ریپو را Public انتخاب کنید.

۲. **محتویات داخل پوشه `education-needs-bi`** را در ریشه ریپو آپلود و Commit کنید؛ `index.html` باید کنار `assets` در صفحه اصلی ریپو باشد، نه داخل یک زیرپوشه دیگر. ZIP را به‌صورت فشرده در ریپو آپلود نکنید. فایل `.nojekyll` هم داخل بسته است؛ اگر هنگام آپلود نمایش داده نشد، یک فایل خالی با همین نام در ریشه بسازید.

۳. به **Settings → Pages → Build and deployment** بروید:

| گزینه | مقدار |
| --- | --- |
| Source | Deploy from a branch |
| Branch | main |
| Folder | /(root) |

۴. Save را بزنید و تکمیل انتشار را در Pages یا Actions ببینید. اگر نام ریپو و حساب مطابق بالا باشد، آدرس داشبورد این خواهد بود:

`https://saeideeshghi.github.io/education-needs-bi/`

پورتال ثبت اطلاعات با آدرس خودش جدا می‌ماند:

`https://saeideeshghi.github.io/education-needs-portal/`

اگر نام ریپوی جدید را عوض کنید، بخش آخر آدرس هم عوض می‌شود. مسیرهای فایل‌ها نسبی هستند و به نام ثابت ریپو وابسته نیستند.

| تحلیل هر حوزه | شاخص‌های حوزه، زیرگروه‌های اصلی جدول، نمودار هر شاخص، همه جفت‌های موجود / موردنیاز و جدول کامل همان حوزه |

دو منبع «جداول اصلی شهرستان‌ها» و «پرونده‌های ثبت‌شده» جدا انتخاب می‌شوند. در منبع پرونده‌ها، فیلتر نوع مرکز، دوره، وضعیت و تاریخ، مبنای snapshot یا آخرین فرم، وضعیت بررسی و آخرین ارسال در ۱۴ روز اخیر هم وجود دارد. فیلدهای تکمیلی و جزئیات اقلام در تحلیل حوزه جدا از ۲۵۰ شاخص نمایش داده می‌شوند.

خروجی CSV، چاپ / PDF مرورگر، حالت روشن و تاریک، منوی موبایل و جدول قابل پیمایش آماده‌اند. عنوان شاخص‌ها و تعریف حوزه‌ها از خود جداول گرفته می‌شود؛ تغییر فیلترها محاسبات را دوباره انجام می‌دهد.

## دریافت اطلاعات پورتال

نمای جداول از داده‌های اصلی همراه پروژه استفاده می‌کند. نمای پرونده‌ها در شروع شامل **۸ پرونده نمونه** است و با برچسب نمایشی مشخص می‌شود.

برای تحلیل اطلاعات ثبت‌شده، از دکمه **دریافت داده** یا منوی **دریافت و مدیریت داده** استفاده کنید:

### دریافت از پورتال همین مرورگر

وقتی هر دو پروژه روی `https://saeideeshghi.github.io` باز شده‌اند، مسیر متفاوت ریپوها مانع دریافت داده نمی‌شود. در همان مرورگر پورتال را باز کنید و اطلاعات را ثبت کنید؛ سپس در داشبورد، **دریافت از پورتال همین مرورگر** را بزنید.

داشبورد یک کپی از پرونده‌های فعلی می‌گیرد. دریافت داده دستی است؛ پس از تغییر پرونده‌ها دوباره این دکمه را بزنید. پورتال از کلید `education-needs-portal:records:v4` و داشبورد از کلید مستقل `education-needs-bi:records:v1` استفاده می‌کند.

اگر یکی از سایت‌ها روی localhost، دامنه سفارشی یا حساب GitHub دیگری باشد، از ورود JSON استفاده کنید.

### ورود و خروج JSON

**ورود فایل JSON پرونده‌ها** یک آرایه پرونده یا یک فایل دارای `records` را می‌پذیرد؛ حداکثر ۵ مگابایت و ۲۵۰ پرونده. فایل خروجی خود داشبورد هم قابل ورود مجدد است.

**دریافت نسخه JSON داده فعلی** برای پشتیبان یا انتقال به مرورگر دیگر است. ورود فایل، مجموعه پرونده‌های قبلی داشبورد را جایگزین می‌کند؛ در صورت نیاز ابتدا نسخه JSON بگیرید.

ساختار پرونده با پورتال نسخه ۴ هماهنگ است:

| فیلد | کاربرد |
| --- | --- |
| id | شناسه یکتا؛ حروف لاتین، عدد، `_` یا `-` |
| county | نام یکی از ۱۰ شهرستان تعریف‌شده |
| code | کد مرکز |
| status | draft / submitted / changes_requested / resubmitted / approved |
| state | profile و sections مربوط به آخرین فرم |
| snapshot | نسخه ارسال‌شده؛ برای پیش‌نویس null |
| updatedAt | زمان آخرین تغییر با فرمت تاریخ معتبر |

هر بخش در `sections` فهرست `rows` دارد؛ هر ردیف با `id`، `value` و `unknown` مشخص می‌شود. شناسه شاخص‌ها در `assets/js/source.js` هستند. مقدار یا بخش غایب، خالی باقی می‌ماند و با داده نمونه پر نمی‌شود.

اگر برای انتقال بین دامنه‌ها به خروجی پورتال نیاز دارید، این کد را در Console مرورگر **داخل صفحه پورتال** اجرا کنید. فایل را دانلود می‌کند و داده پورتال را تغییر نمی‌دهد:

```js
const portalRecordsJSON = localStorage.getItem('education-needs-portal:records:v4');
if (!portalRecordsJSON) {
  alert('داده پرونده‌های پورتال در این مرورگر پیدا نشد.');
} else {
  const portalRecordsURL = URL.createObjectURL(new Blob([portalRecordsJSON], {
    type: 'application/json;charset=utf-8'
  }));
  const portalRecordsLink = document.createElement('a');
  portalRecordsLink.href = portalRecordsURL;
  portalRecordsLink.download = 'education-needs-portal-records.json';
  document.body.append(portalRecordsLink);
  portalRecordsLink.click();
  portalRecordsLink.remove();
  setTimeout(() => URL.revokeObjectURL(portalRecordsURL), 1000);
}
```

این نسخه فقط سمت مرورگر است؛ اطلاعات واردشده بین کاربران یا دستگاه‌ها خودکار به اشتراک گذاشته نمی‌شود. ورود و کنترل دسترسی سمت سرور ندارد. برای جمع‌آوری سازمانی و همگام‌سازی چندکاربره باید API و پایگاه داده اضافه شود.

## منبع داده و روش محاسبه

داده شهرستان‌ها از `county-data.js` پروژه پورتال، بر پایه فایل «جمع آوری داده ها 2.xlsx»، همراه این بسته آمده است. تعریف شاخص‌ها و داده شهرستان‌ها به‌ترتیب در `source.js` و `county-data.js` قرار دارند.

- پوشش داده = تعداد سلول معتبر ÷ تعداد سلول شاخص در محدوده انتخاب‌شده.
- صفر ثبت‌شده معتبر است؛ خالی، `*` و مقدار نامعتبر به صفر تبدیل نمی‌شوند.
- فقط یک شاخص با واحد یکسان بین شهرستان‌ها یا پرونده‌ها جمع می‌شود. سال و متن به‌صورت توزیع نمایش داده می‌شوند.
- «موردنیاز» از «موجود» کم نمی‌شود؛ مقدار درخواست‌شده جدا نمایش داده می‌شود.
- در نمای پرونده‌ها، پیش‌فرض آخرین snapshot ارسال‌شده است و پیش‌نویس‌ها وارد این مبنا نمی‌شوند.
- روند پرونده‌ها شمارش **آخرین ارسال هر پرونده** در روزهای تقویمی تهران است، نه تاریخچه همه ارسال‌ها.
- در فهرست نیازها، مقایسه مقدار و سهم شهرستان فقط در یک شاخص انجام می‌شود. ترتیب شاخص‌ها، رتبه اولویت بودجه نیست.
- بودجه، هزینه و تاریخچه مقادیر شهرستان‌ها در منبع موجود نیست و برای آن‌ها نمودار ساخته نشده است.

داده اصلی فعلی شامل ۲۵۰۰ سلول شاخص است: ۳۳۱ معتبر، ۲۱۴۶ خالی و ۲۳ نامشخص. اختلاف جمع ثبت‌شده ۷۰۶۸ با جمع معلوم ۷۰۶۷ در شاخص `nomadic:r3` به‌صورت هشدار جمع ناقص نمایش داده می‌شود؛ داده منبع تغییر نکرده است.

## اجرای محلی و توسعه

انتشار فایل‌های آماده روی GitHub Pages به npm نیازی ندارد. برای اجرای محلی ابزارها از Node.js 20 یا بالاتر استفاده کنید؛ وابستگی npm وجود ندارد:

```bash
npm start
```

سپس `http://localhost:3000` را باز کنید. اگر در محیط شما متغیر `PORT` تنظیم شده باشد، پورت همان مقدار است.

```bash
npm run build
npm run check
npm test
```

Build فایل‌های `src/analytics.css` و `src/dashboard.css` را به assets کپی می‌کند و یک نسخه قابل میزبانی هم در `dist` می‌سازد. برای روش انتشار این راهنما، فایل‌های ریشه را آپلود کنید. Check نحو JavaScript و مسیر فایل‌ها را بررسی می‌کند. ۳۳ تست منطق تحلیل، کامل بودن شاخص‌ها، انتخاب حوزه و زیرگروه، جست‌وجو، خروجی، انتقال داده و HTML تولیدشده وجود دارند. بررسی بصری در مرورگر در این محیط انجام نشده است.
